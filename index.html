The cipher is fine.
The mode is where it leaks.

AES can only lock one 128-bit block at a time. A mode of operation is the rule for locking a whole message. Pick the wrong rule and your secret is readable — even though the encryption never broke.

Why do we even need a “mode”?

AES is a block cipher. It takes in exactly 128 bits (16 bytes) and gives back 128 bits. That's it. But real messages are never exactly 16 bytes. So we need a rule for feeding a long message through a machine that only accepts one block at a time. That rule is the mode.

Your message gets chopped into 128-bit blocks

block 1128 bits
block 2128 bits
block 3128 bits
block 4 + paddingfilled to 128 bits

The last block is rarely full, so we pad it. The common scheme, PKCS#7, adds n bytes each equal to n — so the receiver always knows exactly how much to remove.

The IV — your “randomiser”

An Initialisation Vector is one extra block that makes the first block come out differently every time. Without it, encrypting the same message twice gives the identical ciphertext — a dead giveaway.

  • It is not secret — it's sent in the clear, usually as the first block.
  • For CBC it must be unpredictable (a predictable IV broke TLS 1.0 — the BEAST attack).
  • For counter modes a nonce must never repeat under the same key. Ever.

A mode chains many of these locks together into one message.

The one operation that powers all of this: XOR

XOR (⊕) outputs 1 only when the two bits differ. Tap the top rows to flip bits and watch the result. The magic property: A ⊕ B ⊕ B = A — XOR the same thing twice and you're back to the start. That's exactly how decryption undoes encryption.

The takeaway

Encryption without authentication is broken by design. Confidentiality (keeping data secret) and integrity (stopping tampering) are two different jobs — and every mode here only does the first. The fix is Authenticated Encryption (like AES-GCM), which bolts a tamper-check onto the mode. That's the next lesson.
